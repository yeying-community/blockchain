## 1. 目标

✅ **建设一份开放的、分层的、人能理解的知识数据集**,同时服务两类读者:

- **给人**:帮助人真正理解知识,而不是只能依赖大模型给答案;
- **给大模型**:作为优质、来源清楚的训练与检索数据。

链的作用是让这份数据集**可确权、可追溯、可回报、可长期保存**。

## 2. 核心原则

| # | 原则 | 含义 |
|---|---|---|
| P1 | **人不是大模型的附属** | 所有知识都必须能被人理解。可理解性是收录与评价的一等标准,而不是附加项 |
| P2 | **链只记账,不裁判** | 链证明它能证明的:谁、何时、贡献了什么、被谁引用和使用、钱怎么流。知识的好坏由使用者与核验者判断,链不假装能裁判"真"与"新" |
| P3 | **来源透明** | 每条知识标明来源:人工撰写 / 模型生成 / 人工核验过的模型生成 |
| P4 | **公共品由网络出资,应用由使用者付费** | 见 §4 |
| P5 | **奖励在世的贡献者** | 创作者推定离世后,收益转给新人(见设计稿 §6) |
| P6 | **不依赖既有权威,质量靠机制收敛** | 不追求每条知识进来时就正确,而是保证整体质量随时间向好收敛。不以外部机构、学历、头衔作为准入或裁决依据;信誉只在系统内积累。**信任靠挣,对内容和对人都一样**:新知识的可信度、新参与者的分量,都从接近零开始 |

P2 的理由:链能可靠证明的是时间戳、签名、未篡改、引用关系和资金流;它证明不了内容的真假、价值和语义上的新颖。
白皮书原叙事"只为可验证的认知增量增发",恰好依赖链证明不了的那一部分。

## 3. 知识分层

✅ 四层,自下而上:

```
应用知识      各领域的具体做法、方案            ← 需被使用或有人出资,才能持续存储
场景化知识    知识在具体情境中怎么用
解释性知识    把基础知识讲明白,帮助人理解
基础知识      坚实的概念、原理、事实            ← 大模型辅助生成初版,人工核验后成为基础;免费存储
```

另有**传承类**(家训、生平、族谱),不属于这四层,不参与增发,靠捐赠本金长期保存。

上层通过**引用**连接下层:应用引用场景,场景引用解释,解释引用基础。

## 4. 经济原则

✅ 资金来源与层级对应:

| 层 | 性质 | 资金来源 |
|---|---|---|
| 基础知识 | 公共品 | 协议增发与国库(网络共同出资) |
| 解释性、场景化知识 | 介于两者之间 | 增发补贴 + 被使用的收益 |
| 应用知识 | 有明确使用方 | 使用付费或资助方出资 |

**推导**:增发的正当性来自"公共品市场不会自发付费,所以由网络出资",而不是"新颖就值钱"。
这与现实中公共资金资助基础研究、企业为应用研究付费是同一逻辑。

基础层虽然免费存储、不收使用费,但被所有上层引用,重要性最高;奖励池分成沿引用链上溯,
所以基础知识的建设者和核验者仍能持续获得回报。

## 4a. 知识单元(Q1 结论)

✅ **一条知识 = 一个知识单元**,满足两条原则:

- **只讲一件事**:一个核心观点或一个核心概念;
- **自身能读懂**:读者不需要先读别的单元,也能理解这一条在说什么(可以引用其他单元来深入)。

参照:维基百科词条太粗(混合多个要点,难以精确引用与确权),知识图谱三元组太细(人读不懂,违背 P1);
采用卡片笔记法"原子卡片"的粒度,加上科研领域纳米出版物"论断 + 来源"的可追溯结构。

**结构**

```
知识单元(固定编号)
 ├─ 层级:基础 / 解释 / 场景 / 应用
 ├─ 版本 v1, v2, v3 …(每次修改一个新版本,旧版本永久保留)
 │    ├─ 语言表达:zh / en / …(同一版本的不同语言,算同一条)
 │    │    ├─ 核心陈述(一两句话)
 │    │    └─ 正文(展开说明、例子、推导)
 │    ├─ 引用:[(单元编号, 引用时的版本号), …]
 │    ├─ 来源:人工撰写 / 模型生成 / 人工核验过的模型生成(模型生成须记录模型名称与版本)
 │    └─ 贡献者:作者、修订者、翻译者、核验者(各自签名)
 └─ 生命周期状态:活跃 / 休眠 / 归档 / 已证伪 / 已取代
```

链上存:单元编号、层级、版本序列、每个语言正文的哈希、引用、来源标记、签名、状态。
正文存在链下(由谁存储见 Q5)。

**各层单元示例**

| 层 | 示例 |
|---|---|
| 基础 | 牛顿第二定律:物体加速度与所受合力成正比,与质量成反比 |
| 解释 | 用推购物车的体验理解牛顿第二定律(引用上一条) |
| 场景 | 为什么汽车满载时刹车距离会变长 |
| 应用 | 货车配载的安全规范计算 |

**解释与基础是分开的单元**:同一条基础知识可以有多种解释,面向不同读者;哪种解释真正帮人理解,
由引用和使用来证明,好的解释得到回报。这是 P1 的落脚点。

**已定规则**

| # | 决策 | 推导出的规则 |
|---|---|---|
| U1 | 所有修改都走**版本化** | 引用记录被引单元当时的版本号;被引单元更新后,提示"引用基于 v2,当前 v4",由引用方作者决定是否跟进。"已取代"只用于不同单元之间(新概念整体取代旧概念),同一单元的修改一律是版本 |
| U2 | 不同语言**算同一条** | 翻译(同样内容,换语言)= 同一单元;新讲法(不论什么语言)= 新的解释单元,提交者声明、评审核对。必须**跨语言查重**,防止把别人的单元翻译后当新单元提交抢署名,这是嵌入向量的明确用途(见 Q7)。翻译者记为该单元贡献者 |

**引用分两类,可信度沿"依据"传递**(2026-11-08,🔶 试运行规则 v0,尚未仿真)

在起草运动健身试运行单元时发现:"渐进超负荷"与"超量恢复"互相提到对方。若引用一律视为依赖,就会成环,
可信度无法传递。实际上引用有两种性质:

| 类型 | 含义 | 传递可信度 | 能否成环 |
|---|---|---|---|
| **依据** | 本单元建立在被引用单元之上;被引用单元若被证伪,本单元也站不住 | 是 | 否 |
| **参见** | 两者相关、可互相补充,但一方出错不影响另一方 | 否 | 可以 |

**有效可信度 = min(自身可信度, 所依据的每个单元的有效可信度)。** 一条知识不可能比它的地基更可信。
自身可信度(试运行参数):模型生成未核验 0.1;人工撰写未核验 0.2;每多一位独立的人对**当前版本**核验通过 +0.2,上限 0.9。
核验只对当时的版本有效,内容改动后须重新核验(与 U1 一致)。

这让**图本身成为可信度机制的一部分**,而不只是导航:
- 可信度自下而上生长,任何一处薄弱都会在依赖它的地方显现;
- 工具能指出每个单元"被谁卡住",以及核验哪个单元能抬高最多下游单元,引导核验工作先打地基;
- 基础单元被证伪或修订时,所有依据它的单元有效可信度随之下降(落实 C4)。

实现:[`tools/kgraph.py`](../tools/kgraph.py)(完整性检查 + 可信度计算 + 优先核验顺序),
在 [`pilot/fitness/GRAPH.md`](pilot/fitness/GRAPH.md) 上运行。**待办**:在收敛仿真中检验该规则(例如是否过于严格,
导致上层知识长期受限)。

**由此产生的新问题**:谁可以发布一个单元的新版本(仅原作者,还是任何人提议、经核验合并)
→ 并入 Q2;修订者、翻译者、核验者之间的收益怎么分 → 并入 Q5;链下正文由谁存储 → 并入 Q5。

## 4b. 质量收敛机制(Q2,🔶 讨论中)

**安全目标**:**按影响力加权的错误比例随时间下降。** 系统不保证每一条都对,保证的是错误在最要紧的地方
最快被发现和修正。只要这一收敛性成立,架构就是安全的(类比比特币:不保证每个节点诚实,只保证诚实者
占多数时整个系统收敛到同一条链)。

**核心思路:准入宽,信任靠挣。** 每个知识单元在"层级"之外有一个**可信度**:层级说"这是什么类型的知识",
可信度说"它目前有多可靠"。新内容可信度从低起步、影响力很小;经受住挑战、被持续使用后,可信度才上升。

由此,**新研究成果 = 一条可信度还低的基础单元**;只有可信度达标的基础单元才享受基础层待遇(免费存储、
高影响力)。基础层的地位是挣来的,不是提交时声明的。

**五个机制**

| # | 机制 | 作用 |
|---|---|---|
| C1 | **挑战有奖**:任何人可押注挑战任何单元;成立则挑战者获得提交者与核验者被罚没的押金,不成立则挑战者押金被罚没 | 找错比犯错更赚钱,形成长期"找错悬赏" |
| C2 | **悬赏与影响力挂钩**:被挑战单元影响力越大,悬赏越大 | 越重要的知识越多人去查,错误在要紧处最快被发现;这是收敛性的关键 |
| C3 | **内部信誉**:人人从零开始,信誉只来自系统内记录(贡献是否站住、核验是否正确、挑战是否成立),按领域计算,随时间衰减 | 不导入外部权威;防止早期参与者永久把持话语权 |
| C4 | **修正沿引用链传播**:单元被证伪或修订,引用它的单元收到提示(依赖 U1 的版本记录) | 错误不会悄悄留在上层 |
| C5 | **前期保守**:可信度设上限,上限随网络规模放开 | 早期参与者少、检验力度弱,防止少数人把错误固化为"基础" |
| C6 | **前期社区驱动**(2026-11-07 确定,接受前期慢):起步阶段以社区为主导,目标聚焦,打牢底座。创始社区受三条约束:信誉同样随时间衰减;早期每个判断都可被挑战,无"元老豁免";C5 的可信度上限同样适用 | 防止创始社区成为新的权威(P6) |

**责任机制(2026-11-07 确定:奖惩分明,罚不负责任,不罚少数意见)**

奖惩的对象是**是否负责任**,而不是"是否与多数意见一致"。否则系统会用奖惩清理掉推动认知提升的少数派
(地心说年代,日心说的提出者和支持者会被罚)。

| 类型 | 例子 | 处理 |
|---|---|---|
| 作恶 | 编造、剽窃、刷分 | 重罚:押金没收,信誉清零 |
| 失职 | 核验者放过**当时就能查出**的事实错误 | 罚:按程度扣押金与信誉 |
| 诚实的错 | 地心说:当时证据下的最好理解,后被更好的认识取代 | **不罚**:原单元标"已取代",保留历史地位,已获收益不追回 |
| 推动认知提升 | 日心说:作为少数派提出,后被证实 | **追溯奖励**:越早、越是在少数时支持,奖励越高 |

**失职与诚实的错由时间戳判定**:推翻它的证据是否早于核验存在。证据早于核验 ⇒ 本该看到,属失职;
证据晚于核验 ⇒ 当时无从知道,属诚实的错。链上记录每条知识、证据、核验的时间,判定客观,不需要权威。
**每个人只对自己当时能知道的东西负责。**

**争议分类**

| 类型 | 例子 | 处理 | 是否有人受罚 |
|---|---|---|---|
| 事实性错误 | 数字、引文、公式错误 | 挑战裁决,快速处理 | 是(作恶或失职) |
| 表述不准确 | 漏了适用条件、说法太绝对 | 发布新版本修正(U1),修订者记功 | 否 |
| **认识之争** | 地心说与日心说;量子力学的不同诠释 | **不强行裁决**:双方作为独立单元并存,标"竞争关系",靠证据与使用随时间分出高下 | 否;胜出方追溯奖励 |
| 立场之争 | 伦理判断、历史评价 | **永不裁决**:多种观点并存,链只记录谁持何观点、理由是什么 | 否 |
| 垃圾内容 | 无意义内容、重复刷单 | 快速清理 | 是 |

**挑战共识不用"举报",而用"提交竞争单元"**:举报会进入裁决、可能被多数压制;竞争单元与原单元并存,
链上显示为一处"断层"(白皮书 §8),之后由引用、使用与检验决定可信度消长。争议是认知提升的关键,
机制要保护它,而不是消灭它。

**失效条件(必须正视)**

| 失效情况 | 缓解 |
|---|---|
| 多数裁决者串通或犯错 | 申诉逐级扩大裁决范围,作恶成本随级数上升;信誉衰减 |
| **普遍的误解**:多数参与者相信同一个错误 | 挑战须给出证据与推理,裁决评判论证而非投票;败诉的少数意见保留在链上,可日后翻案 |
| 前期无人检查 | C5 |

**认识论立场**:这个系统收敛到的是"参与者集体能达到的最好理解",不是绝对真理。科学本身就是这样运作的:
没有机构握有真理,只有可被挑战、可被修正的当前最好理解。

**验证方式**:把"影响力加权错误比例随时间下降"写成收敛条件,用 `sim/` 智能体仿真检验:不同的错误提交率、
作恶者比例、悬赏强度、早期参数下,错误比例是否下降、在什么条件下失控。

**仿真结论(2026-11-07,`sim/convergence.py`,8 种子 × 200 期,结果见 [`sim/CONVERGENCE.md`](../sim/CONVERGENCE.md))**

*第一轮(上述草案)*:错误带有隐蔽性时(尤其是大模型的编造),**草案不收敛**:加权错误率 3.5% → 4.3% 持续上升,
末期在册知识约 20% 有错。根因是**审查能力被提交量摊薄**:网络越大,平均每条知识被检查得越少。
C2、C3 在模型中无可测量作用;C5 反而有害(创始社区诚实时,早期影响力集中在他们身上本是好事)。

*第二轮*:加入三项机制后,加权错误率**稳定在 1.2%,不再随规模上升**;在 80% 大模型初稿、自愿审查积极性低、
作恶者占 35% 等压力场景下同样稳定;作恶者占 50% 时勉强扛住(中途 10.6%,末期 5.0%)。

| # | 新机制 | 单独效果(末期加权错误率,基准 4.3%) |
|---|---|---|
| M1 | **审查义务**:每提交一条知识,须审查 2 条他人的(类比"投稿人也要做审稿人") | 2.4% |
| M2 | **精准审查**:审查对准"影响力大、且尚未被充分检验"的内容(替代 C2 的"只按影响力") | 2.5% |
| M3 | **理性作恶者**:持续亏损即停手。这不是新机制,而是修正第一轮低估了责任机制的威慑作用 | 2.3% |
| — | 三者合用 | **1.2%**,全程稳定 |

**安全目标修正**:只要有新知识进入,就有新错误进入,错误率不可能降为零。安全目标修正为:
**影响力加权错误率保持在有界的低水平,且不随网络规模扩大而上升。**

**可靠的结论**(两轮、多场景一致)
1. **审查必须是义务,不能靠自愿**(M1)。审查能力必须与提交量同步增长。
2. **责任机制必需,其核心作用是威慑**:去掉后作恶重新有利可图(+1.9),正确知识被误删翻四倍以上。
3. **争议用竞争单元、不罚诚实的错**:多数裁决模式下约七成开拓者被清理,诚实者被罚一两百人次;本设计下开拓者存活率 0.98。

**尚不可靠的结论**
- C5 前期影响力上限:仿真未支持,**暂缓**(不删除)。它防范的"创始社区固化错误"由 C6 约束处理。
- C3 信誉衰减:无可测量作用,保留理由是原则性的(防止永久把持话语权)。

*第三轮*:放松第二轮中四个偏乐观的假设,逐个检验并设计对策。

| 放松的假设 | 不加对策 | 对策 | 加对策后 |
|---|---|---|---|
| A1 70% 的人义务审查走过场,且自愿审查也很少 | 1.6%(早期约 5%,之后下降) | M4 审查问责:放过当时可检出错误的审查者事后受罚 | 1.4%,**作用不明显** |
| A2 作恶者抱团:互相引用、用义务审查互相背书 | 2.2%(早期峰值 7%) | M5 引用分量看引用方信誉(设计稿 §3 本有此规定) | 1.3% |
| A3 资金雄厚的作恶者亏损也不停手 | 1.9%,正确知识被误删 24.9 次 | M6 只对信誉烧光的账户限流 | 0.9%,误删 11.9 次 |
| A4 女巫:信誉烧光就换新账户 | 2.2% | M7 新人见习期 | 0.8% |

A1 不构成致命问题:义务审查量随提交量增长,哪怕多数人走过场,认真的少数乘以总量仍然够用;再加上精准审查(M2)。

**第三轮最重要的发现:"信任靠挣"同样适用于人,不只是内容。** 第一版 M5、M4 按"信誉 ÷ 新人基线"折算,
新人默认就是满分量。于是女巫每次换号,信誉回到基线,就能用满分量的新账户继续互引互背书——**换号等于洗白**。
修正为**新人的分量从接近零开始,随账龄和记录增长**后,最坏情况(作恶者 10%)从 6.8% 且上升,变为 2.4% 且下降后稳定。

**硬边界**:四个假设同时放松(作恶者预算无限、抱团、换号,审查者走过场)时:

| 作恶者占新加入者 | 末期加权错误率 | 判断 |
|---|---|---|
| 10% | 2.4%,下降后稳定 | 守住 |
| 20% | 6.3%,仍在上升 | 失守 |
| 35% | 13.6%,仍在上升 | 失守 |

**开户成本对预算无限的攻击者无效**:开户成本提高到 5 倍、20 倍,错误率完全不变,只是作恶者多花钱。
用钱设门槛,只能挡住预算有限的攻击者(现实中的多数攻击者)。

**对诚实者的代价**:无攻击者时,M6 与 M7 使在册知识减少约 20%(新人见习期内提交打折、偶尔犯错者被限流)。
这是前期慢的一部分代价(已接受,见 C6)。早期质量因此更好(前 10% 时期加权错误率 1.6%,对照 3.1%)。

*第四轮*:检验 M8 邀请担保、有限预算的攻击者、作恶收益对攻击者数量的反馈。

**M8 邀请担保**:新成员(包括换号)须由过了见习期的老成员担保;诚实担保人以一定概率识破作恶申请人;
作恶者可以互相担保;被担保人**作恶被查实**时担保人连带受罚。

> 设计细节(仿真发现):连带责任**只针对作恶**(编造、恶意挑战),不针对失职或诚实的错。担保的是"此人不会作恶",
> 不是"此人从不犯错"。最初版本对任何信誉烧光都追责,无攻击者时诚实者人均收益下降 17%;收窄后代价归零。

| 最坏攻击者(预算无限、抱团、换号,审查走过场) | 无 M8 | 有 M8 |
|---|---|---|
| 作恶申请者 20% | 6.3%,上升 | 3.8%,缓慢上升 |
| 作恶申请者 35%,担保人把关松(识破率 0.2) | — | 11.7% |
| 作恶申请者 35%,把关一般(0.5) | 13.6%,上升 | 7.6% |
| 作恶申请者 35%,**把关严(0.8)** | — | **3.8%,基本稳定** |
| 作恶申请者 50% | — | 17.1%,失守 |

M8 的效果**几乎完全取决于担保人把关的严格程度**,也就是社区成员自身的判断力。

**有限预算的攻击者**(每人预算 30,作恶申请者 20%,无 M8):开户成本为 1 时 4.5%;**提高到 5 倍时 2.5%,
攻击者预算耗尽、全部停手**。对现实中预算有限的攻击者,开户成本是有效的。

**作恶收益吸引更多攻击者**(起点 10%,有利则攻击者比例上升,不利则下降):
有责任机制时作恶亏钱,攻击者不增反减,末期 2.0%(有 M8 时 1.6%);
**关掉责任机制,作恶有利可图,攻击者越来越多,错误率升到 49%,系统崩溃。**

**四轮推演的总结论**

1. **整个系统的安全建立在"作恶不划算"之上。** 一旦作恶有利可图,攻击者会越来越多,其他机制都挡不住。
   责任机制(奖惩分明)是地基,不是附加项。
2. **对预算有限的攻击者**(现实中的大多数),内部机制加开户成本就够了。
3. **对预算无限的攻击者**,唯一有效的是控制谁能进来(M8),而 M8 的效果取决于社区成员把关的严格程度。
   所以**前期的真正安全参数是社区本身的质量**,这为 C6"前期社区驱动、宁慢勿滥"提供了量化依据。
4. **硬边界**:预算无限的攻击者占申请者 35% 以上且社区把关一般,或占 50%,现有机制都守不住。
   这与所有开放共识系统一样存在容错上限(类比 BFT 的 1/3)。

| 机制 | 作用 | 仿真支持 |
|---|---|---|
| 责任机制 | 作恶不划算,攻击者不增反减 | 强 |
| M1 审查义务 | 审查能力随提交量增长 | 强 |
| M2 精准审查 | 审查对准影响大而没查透的 | 强 |
| M5 引用看信誉 | 抱团互引失效 | 强 |
| M6 信誉烧光者限流 | 不停手的攻击者被限流 | 强 |
| M7 新人见习期(新人分量从零起步) | 换号不再等于洗白 | 强 |
| M8 邀请担保(只对作恶连带) | 控制谁能进来 | 中:取决于把关严格程度 |
| 竞争单元、不罚诚实的错 | 保护开拓者 | 强 |
| M4 审查问责 | 防走过场 | 弱:无可测量作用,按原则保留 |
| C3 信誉衰减 | 防永久把持 | 弱:按原则保留 |
| C5 前期影响力上限 | — | 未支持,暂缓 |

**推演的边际收益在下降。** 决定安全的三个参数——**审查者发现错误的能力、担保人把关的严格程度、
攻击者的比例与预算**——在模型里都只能假设,只有在真实运行中才能测量。下一步应在起步领域(Q8)做小规模试运行,
测量这三个参数,再回到仿真校准。

**被否决的方案**:~~基础层以"至少两个外部权威来源佐证"为准入门槛;核验者需领域资格。~~
否决原因(2026-11-07):把判断权交给既有机构,违背 P6;且前期最难执行(无人有资格、无法为所有内容找到权威出处)。
外部文献仍可作为挑战与核验中的**证据**提交,但不具备自动的权威地位。

## 4c. 起步领域与人群(Q8)

**选领域的六条标准**:社区真懂(前期核验靠社区,C6)、层次分明(四层结构能完整跑起来)、有人真用、
对错能检验(前期参与者少,收敛最脆弱)、错了危害小(机制未成熟时避开医疗、法律)、贴合使命(P1)。

| 候选 | 社区真懂 | 层次分明 | 有人真用 | 对错能检验 | 错了危害小 | 贴合使命 |
|---|---|---|---|---|---|---|
| **大模型应用开发** | 高 | 高 | 高 | 中高(多数可跑代码验证) | 高 | **最高** |
| 软件工程与运维实践 | 高 | 中 | 高 | 高 | 高 | 中 |
| 中小学基础学科 | 低 | 高 | 高 | 高 | 高 | 中 |
| 区块链与分布式系统 | 高 | 高 | 低 | 中 | 高 | 低 |
| 健康医学科普 | 低 | 中 | 高 | 低 | 低 | 中 |

**建议**:从**大模型应用开发**起步,面向**用 AI、但想真正理解 AI 的开发者**。
- 这个人群正在成为大模型的附属:复制提示词、套用框架,说不清 token、上下文窗口、嵌入、注意力是什么;
- 领域信息混乱:营销多、过时快、文档各讲各家,少有人把"原理 → 讲清 → 何时用 → 怎么做"串成一条线;
- 四层自然成立:基础(token、注意力、上下文窗口)→ 解释(模型为什么"记不住"很久前说的话)→
  场景(何时用检索增强、何时微调)→ 应用(给客服系统搭检索增强流程);
- 能完整检验机制:应用层过时快,检验生命周期;前沿争议多,检验"认识之争不强行裁决";
- 元叙事:用大模型辅助生成初版、由人核验成可理解的知识,解释的对象正是大模型本身;
- 为 Q6 铺路:来源清楚、经核验、讲清原理的数据对 AI 团队有直接价值。

**风险**:领域变化快。基础层只收相对稳定的原理(几年内不变);变化快的内容放应用层,由生命周期自然淘汰。

**社区**:夜莺社区以软件工程为主、日常大量使用 AI Agent(✅ 2026-11-07 确认)。
社区希望做**重要且有意义**的事,而不只是开发者工具。

### ✅ 决定:两个起步领域(2026-11-07)

1. **大模型应用开发**,面向用 AI、但想真正理解 AI 的开发者;
2. **运动健身**,面向**久坐、时间少、想保持健康的现代成年人**:针对不同的运动给出可解释的知识和示例,
   帮助现代人保持健康状态。避免产品过于技术。

> 修订记录:最初拟为"健康生活(运动、饮食、作息)",同日聚焦为"运动健身"。理由:营养学争议过多、对错难检验、
> 危害较高;运动生理原理较稳定,动作可演示可对照,社区里也更容易找到懂行的人。

**意义**:AI 和身体,是今天每个人都绕不开、又最容易失去自己判断的两件事。练健身的人多半照着视频和别人的计划做,
不知道为什么,所以容易练错、练伤、坚持不下去。让每个动作、每个计划都能追溯到原理,人就能自己判断、自己调整(P1)。

**两个领域互为对照**,试运行可测出"审查者发现错误的能力"在不同领域的差距,用于校准仿真:

| | 大模型应用开发 | 运动健身 |
|---|---|---|
| 对错能否检验 | 容易,许多可跑代码验证 | 较容易:原理稳定,动作可演示可对照;效果因人而异 |
| 社区是否擅长 | 擅长 | 较擅长:工程师中跑步、力量训练者多,教练与运动康复从业者也较易找到 |
| 错了的危害 | 小 | 中:主要是受伤风险 |
| 争议多少 | 中 | 中 |

### 运动健身的知识结构

| 层 | 内容 | 示例 |
|---|---|---|
| 基础 | 通用运动原理 | 渐进超负荷;超量恢复;有氧与无氧的能量供应;心率区间;肌肉收缩方式;关节的稳定与灵活 |
| 解释 | 把原理讲明白 | 为什么力量训练后同一块肌肉要隔一两天再练;为什么跑步膝盖疼常与臀部力量不足有关 |
| 场景 | 现代人的具体处境 | 久坐上班族的腰背僵硬;每周三次、每次 30 分钟怎么安排;出差无器械;40 岁后开始运动 |
| 应用 | **按运动分类**的具体做法 | 跑步、力量训练(深蹲、硬拉、俯卧撑等)、游泳、骑行、拉伸与瑜伽、跳绳、球类、徒步 |

**每个应用单元包括**:怎么做(要领、强度、频率、进阶)、**为什么**(引用所依据的基础原理)、常见错误及原因、
一个具体的训练示例、适用人群与禁忌。例:"深蹲"引用"渐进超负荷""髋关节与膝关节的协同""核心稳定",
读者不只知道怎么蹲,还知道为什么膝盖要与脚尖同向、负重怎么加才安全。

### 运动健身的安全边界

| 收录 | 暂不收录(机制跑稳、社区有懂行的人后再放开) |
|---|---|
| 健康成年人的一般性锻炼 | 伤后、术后康复训练 |
| 各项运动的技术要领与进阶方法 | 孕妇、未成年人、慢性病人、有基础疾病的老年人 |
| 热身、恢复、预防运动损伤的基础知识 | 竞技与职业运动员训练方案 |
| 久坐人群的常见问题 | 补剂、兴奋剂、极端减重;饮食方案 |

其他规则:
1. **应用单元必须写明适用人群、禁忌与强度等级**(在此领域从可选变为必填);
2. **补充懂行的人,但不给特权**:邀请教练、运动康复背景的成员加入创始社区,与其他人一样从零积累信誉(P6);
3. **证据要附,但不是权威**:有争议的问题(如运动前静态拉伸、空腹有氧)按"认识之争并存、不强行裁决"处理;
4. **规则更严**:见习期更长、可信度上限更低。

**起步分量**:两个领域同时起步。大模型应用开发约 100 条基础知识;运动健身先约 50 条。

**起草助手**:运动健身领域有项目级技能 [`.claude/skills/fitness-knowledge`](../.claude/skills/fitness-knowledge/SKILL.md),
负责按模板起草初稿、为人类审查者生成检查清单、拦下超出安全边界的内容。**它是助手,不是审查者**:产出一律标为
"模型生成、待核验";模型起草再由模型审查,错误高度相关,会使多人审查的纠错能力失效(§4b)。
示例草稿见 [`pilot/fitness/`](pilot/fitness/)。**懂行的人仍需寻找**,第一批运动健身知识至少需一两位懂行的人核验。

大模型应用开发领域有对应的技能 [`.claude/skills/llm-knowledge`](../.claude/skills/llm-knowledge/SKILL.md),规则相同;
额外要求每个单元附**读者可以自己动手的验证**(可运行的代码或可重复的实验),并特别防范"模型解释模型自己"时
把流行说法当成事实。首批 9 个单元(四层各有一例)见 [`pilot/llm/`](pilot/llm/)。

## 4d. 测试网与主网迁移(✅ 2026-11-08)

**路线**:先搭建由社区驱动的测试网;主网上线时,测试网的数据作为主网的启动数据。

| # | 决策 |
|---|---|
| T1 | **迁移范围**:知识单元(内容哈希、全部版本、引用、来源标注)、核验记录、贡献记录、成员与邀请关系**迁移**;代币余额**不迁移**;信誉**不直接迁移**,主网按主网规则从迁移的记录重新计算 |
| T2 | **内容许可:CC BY 4.0**。任何人可使用(含商用),只需署名。协议强制,提交即同意;必须在第一条社区贡献之前生效 |
| T3 | **等链上知识单元模型做好再开测试网**(不走"Git 协作 + 链上锚定"的过渡方案) |

**T1 的理由**:若测试网的余额或信誉可以兑换主网收益,测试网会成为刷分目标,而测试网恰是防御最弱的时候。
这违背仿真最重要的结论:安全建立在"作恶不划算"之上(§4b)。早期贡献者的回报:**完整保留贡献记录,
不提前承诺任何兑换关系**,主网上线后由治理决定。

**迁移可验证**:主网创世写入测试网最终知识快照的哈希与测试网最后区块的哈希,任何人可从测试网历史重新计算核对。

**测试网的局限**:测试网不发放有价值的代币,基本不会有攻击者。它能测出诚实参与者的参数(核验认真程度、
知识错误率),但测不出对抗参数(攻击者比例、担保人把关严格程度),后者要等阶段 2 经济机制上线后再测。

**链上模型设计**:[`design/knowledge-units-onchain.md`](design/knowledge-units-onchain.md)(阶段 1:知识单元、版本、
两类引用、核验、可信度、邀请与见习期;不含经济机制)。

**测试网参数(2026-11-08)**:见习期 7 天、邀请冷却 1 天(按每秒一块折算);第一批成员自己生成密钥、只提交公钥,
组织者用 `testnet/gen.sh --members` 开链(见 `testnet/MEMBERS.md`)。

**进度(2026-11-08)**:阶段 1 的 7 个分片(K1–K7)全部完成并实测:4 节点测试网上导入运动健身单元、可信度沿依据传递、
soak 与 chaos 演练通过、知识状态跨节点逐字节一致。**链上知识单元模型已就绪,测试网可以开启**(T3 的前提已满足)。

## 5. 已确定的机制决策

来自 2026-11 设计讨论,详见 [`design/knowledge-lifecycle-economy.md`](design/knowledge-lifecycle-economy.md)。
该设计稿基于旧的"理论 / 领域 / 应用"三层写成,**需要按本文 §3 的四层重新对齐**。

- 重要性由被引用决定,近期引用权重高,随时间衰减;
- 知识有生命周期:活跃、休眠、归档、已证伪、已取代;各层有自然期限;
- 引用免费,但引用方需持有余额,门槛随引用条数递增;
- 作者的持续收入来自按重要性分配的奖励池,20% 沿引用链上溯;
- 存活心跳判断推定离世(静默 4 年),平均寿命只用于调节;离世后收益转入新人基金;
- 不引入实名;接受继承人代签报平安的漏洞,由静默期与高龄上限限时。

## 7. 已知风险

- **模型编造**:大模型生成的初版存在事实错误;基础层错了,上层都建立在错误之上。→ Q4
- **模型崩溃**:用模型生成的数据反复训练模型,质量会逐代退化(Shumailov 等,《Nature》2024)。
  数据集若以模型生成内容为主,又用于训练模型,会形成自我循环。→ P3、Q4
- **免费层被滥用**:基础层免费,所有人都想把内容标成"基础"。→ 基础层准入最严、规模受控,Q2
- **增发依赖**:增发随链龄递减,长期奖励规模取决于外部付费。→ Q5、Q6
