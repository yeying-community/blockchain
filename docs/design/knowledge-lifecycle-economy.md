## 1. 目标与非目标

**目标**
- 让"重要的知识"可计算:重要性随引用增长,也随时间衰减。
- 让知识有完整的生命周期:诞生、活跃、休眠、归档、证伪或被取代。
- 形成经济闭环:有来源,也有消费,而不是只增发。
- 奖励在世的贡献者;创作者离世后,收益转向新人,形成代际循环。
- 支持传承类记录(生平、家训),但不让它成为刷币的口子。

**非目标**
- 不把蕴含、反驳、争议等语义边放进共识。它们本身是需要验证的论断,留在评审层和链下视图。
- 不在链上存储正文。链上只存哈希、元数据、嵌入和签名。
- 不做实名身份系统。

## 2. 节点类型与分层

### 2.1 层级

| 层 | 例子 | 被引用节奏 | 自然期限 | 准入 | 参与 ΔK 增发 |
|---|---|---|---|---|---|
| 理论 `Theory` | 信息论、博弈论 | 慢而久 | 50 年 | 评审 + 复现 | 是 |
| 领域 `Domain` | Transformer、某疾病机理 | 中等 | 20 年 | 评审 | 是 |
| 应用 `Application` | 调参技巧、产品方案 | 快热快冷 | 5 年 | 评审(门槛较宽) | 是 |
| 传承 `Heritage` | 生平、家训、族谱 | 以代际计 | 由捐赠本金决定 | ≥2 名见证人背书 | **否**(D4) |

现有的 `domain: u32` 保留,表示领域命名空间;新增 `layer` 字段与之正交。新颖度比较的范围从"同一领域"改为"同一层级、同一领域"。

### 2.2 引用边

链上只引入一种边:**引用 `CITES`**,即新节点在提交时声明它引用了哪些已有 `node_id`。

规则:
- 只能引用已存在的节点(含休眠和归档节点),不能引用自己,不能引用未来的节点。所以引用图天然无环。
- 单个节点的引用数设上限(默认 32),防止一次性"撒网引用"。
- **引用免费,但引用方必须有余额**(D11)。门槛随引用条数递增:
  ```
  所需余额 = 基础门槛(默认 1 $COG) + 每条引用门槛(默认 0.1 $COG) × 本次引用条数
  ```
  只检查、不扣除、不冻结。这样既不打击正常引用,又能挡住零余额小号的批量刷引用:一次引用
  32 条需要的余额是只引用 2 条的十几倍,刷引用的成本随规模上升。余额门槛与既有的押金、手续费
  覆盖检查同处一次准入校验(见 §9 映射)。
- **同一作者的引用不计入重要性,也不产生收益**(防止自我刷分)。
- 引用方向不做强制,但正常情况下是应用引用领域、领域引用理论,传承引用理论或领域(例如家训引用经典)。

引用写在提交交易里,由作者签名,是共识状态的一部分。

## 3. 重要性

### 3.1 定义

```
I(n, t) = I₀(n) · 2^(−(t − t_n) / H(n))  +  Σ_{c 引用 n} w(c) · 2^(−(t − t_c) / H(n))
```

| 符号 | 含义 |
|---|---|
| `I₀(n)` | 初始重要性,等于节点诞生时的 ΔK(传承类为 0)。解决新知识的冷启动 |
| `t_n`, `t_c` | 节点诞生高度、引用发生高度 |
| `H(n)` | 该节点所在层级的重要性半衰期:理论 10 年、领域 4 年、应用 1 年、传承 25 年 |
| `w(c)` | 引用权重 = 引用方在引用发生时的重要性(有上限),同作者引用为 0 |

### 3.2 为什么这样定义

- **"在世"可计算**:`I(n, t) ≥ I_alive` 的知识就是活着的知识。最近还在被引用,说明它还在被使用。
- **新知识不吃亏**:靠 `I₀` 起步,引用随后接力。
- **防刷**:引用权重来自引用方自己的重要性,一群新注册的空节点互引几乎不产生权重。

### 3.3 可实现性

- **不做 PageRank 迭代**。`w(c)` 取引用方**在引用发生那一刻**的重要性快照,之后不再回算。每条引用 O(1),结果确定。
- **惰性衰减**。每个节点只存 `(I_last, t_last)`;读取或新增引用时,先按经过的高度把 `I_last` 衰减到当前,再加新权重。不需要每个周期扫描全图。
- **定点数**。重要性用 `u64` 定点表示(放大 10⁶);衰减因子沿用共识路径已有的 `libm` 位级确定实现,与 `time_decay` 一致。

## 4. 知识生命周期

### 4.1 状态机

```
                 引用使 I 回升到 I_alive 以上(并补缴租金)
              ┌──────────────────────────────────────┐
              ▼                                      │
 诞生 ──▶ 活跃 Active ──(租金断缴 或 自然期限到期未续)──▶ 休眠 Dormant ──(休眠超 2 年)──▶ 归档 Archived
              │                                                                     │
              │                                                  任何人付复活费 ────┘
              ├──(评审判定错误)──▶ 已证伪 Refuted
              └──(评审判定被新知识取代)──▶ 已取代 Superseded
```

| 状态 | 参与奖励池 | 收取租金 | 可被引用 | 留在活跃状态集 |
|---|---|---|---|---|
| 活跃 | 是 | 是 | 是 | 是 |
| 休眠 | 否 | 否 | 是 | 是 |
| 归档 | 否 | 否 | 是(只计历史,不复活) | **否**,只保留承诺和证明 |
| 已证伪 | 否 | 否 | 是(作为"断层"记录) | 是 |
| 已取代 | 否 | 否 | 是,其后续引用的一部分转记给取代者 | 是 |

**销毁不是物理删除**:节点的 `node_id`、cNFT 和历史证明永久有效。归档只是把节点移出活跃状态集,以控制共识状态的规模。

### 4.2 自然期限(D5)

每个节点有一个与层级相关的最长存活期,到期必须续期:

- **应用、领域**:期限内重要性达到续期门槛 `I_renew`,自动续一个期限;否则进入休眠。
- **理论**:续期需要重新评审,不只看引用量。理论一旦被确认,影响面最大,值得定期复核。
- **传承**:不设自然期限,只要捐赠本金还能覆盖租金就一直保存。

### 4.3 证伪与取代

新增两种评审操作:`Refute { node, evidence }` 和 `Supersede { old, new }`。准入与知识提交相同:评审人声誉加权过半。
- 被证伪的节点停止一切收益,但保留为记录,这就是白皮书 §8 的"断层"。
- 被取代的节点,其后续被引用产生的重要性和版税,按比例(默认 30%)转记给取代它的新节点。这对应"范式转换":旧知识的影响力平滑地移交给新知识。

## 5. 经济闭环

### 5.1 资金流

```
┌─────────────────────────── 来源 ───────────────────────────┐
│ ① 协议增发:新知识诞生时的 ΔK 奖励(稿费),随链龄递减(已有 decay_half_life)  │
│    + 每周期注入在世知识奖励池的增发份额,同样随链龄递减                       │
│ ② 外部付费:写入费 · 可验证检索费 · 传承捐赠本金(引用免费,D11)             │
│ ③ 国库:罚没所得(已有)                                                   │
└───────────────────────────────┬────────────────────────────┘
                                ▼
┌─────────────────────────── 分配 ───────────────────────────┐
│ 稿费    → 作者,一次性(现有 cNFT 铸造路径)                                 │
│ 奖励池  → 每周期按活跃节点的重要性 I 加权分配到各节点收益账户;                 │
│           每份分成中默认 20% 沿引用上溯给被引知识(理论层由此持续获益)          │
│ 作者在世 → 可从节点收益账户提取;作者推定离世 → 进托管 → 新人基金(§6)         │
└───────────────────────────────┬────────────────────────────┘
                                ▼
┌─────────────────────────── 消费 ───────────────────────────┐
│ 存储租金:每个活跃节点每周期按占用缴纳,从节点收益账户扣除                     │
│ 租金去向:50% 销毁(对冲增发)、50% 入国库                                    │
│ 手续费中固定比例销毁                                                         │
└────────────────────────────────────────────────────────────┘
```

### 5.2 两个关键设计

**节点收益账户**。每个节点有一个独立的收益账户,奖励池分成先进这里,租金也从这里扣。
- 收益覆盖租金:节点自我维持,作者提取结余。
- 收益不够:节点进入休眠,**不会动用作者钱包里的其他资金**。
- 这样"销毁"成了市场机制:重要的知识自己养活自己,不重要的自然退场,不需要谁来宣判。

**持续收入只有一个来源:奖励池**(D11 引用免费的推论)
- 引用不收费,所以没有"按次付给作者的版税"。
- 被引用提高节点的重要性 `I`,重要性决定它在每周期奖励池里分到多少。效果仍是"被引用越多、越近,
  收入越多",只是钱来自奖励池,而不是引用者直接支付。
- 每份奖励池分成中,默认 20% 按引用关系上溯给被引知识,使很少被直接引用的理论层也能持续获益。
- 稿费是一次性的,奖励池分成是持续的。
- 奖励池的资金来自协议增发份额、外部付费(检索费、写入费)和国库,所以**外部付费的规模直接决定
  长期奖励的规模**——这是 §5.3 必须落地的原因。

### 5.3 外部付费方

只靠增发撑不住,闭环必须有外部资金进入:

| 付费方 | 付什么 | 换来什么 |
|---|---|---|
| AI Agent 与应用 | 可验证检索费(按次) | 带证明的 k 近邻与范围检索结果(已有 M26、M27 原语) |
| 研究者与机构 | 写入费 | 带新颖性检查的优先权证明(cNFT) |
| 个人与家族 | 传承捐赠本金 | 长期保存(§7) |

## 6. 创作者存活与新人基金(D7–D10)

### 6.1 链上能判断什么

链上没有"人",只有密钥。链能观察到的只是"某个密钥还在不在签名"。所以本节判断的是**推定离世**,不是确认离世。这与法律做法一致:《民法典》第 46 条,自然人下落不明满四年,可宣告死亡。

### 6.2 为什么不能直接用平均寿命判定

联合国《世界人口展望 2024》,全球出生时预期寿命约 73 岁,各国从 50 多岁到 85 岁左右不等。直接以此为线有三个问题:
1. 平均数意味着大约一半人活得更久,会把大量健在的老人误判为离世。
2. 出生时预期寿命不适用于已经年长的人,年长者应看剩余预期寿命。
3. 链不知道一个人的年龄,自报年龄可以造假。

所以平均寿命只用作调节,不用作分界线。

### 6.3 判定规则

| 机制 | 规则 | 说明 |
|---|---|---|
| 存活心跳 | 密钥的任何签名操作都更新 `last_active`;另设一个零费用的 `Heartbeat` 操作,专门用来"报平安" | 不需要任何身份信息 |
| 静默推定 | 个人账户连续 **4 年**无签名 → 推定离世 | 对齐《民法典》第 46 条 |
| 年龄加速(可选) | 提交出生年份并经 ≥2 名见证人背书后:超过所在国平均寿命,静默期缩短为 **1 年** | 平均寿命的用法是"从此更频繁地确认",不是判死 |
| 高龄上限 | 超过 **105 岁**且近 1 年无签名 → 推定离世 | 用高分位年龄兜底 |
| 机构与 Agent | 无年龄;连续 **5 年**无签名 → 按离世处理(D10) | 运营方定期签名即可续期 |
| 宽限托管 | 推定离世后 **2 年**内,收益进托管;本人重新签名即恢复,托管全额返还 | 对应《民法典》第 50、53 条:撤销死亡宣告、返还财产 |

各国平均寿命表作为治理参数上链,依联合国数据由提案更新;未登记国家用全球默认值 73。

### 6.4 什么转给新人,什么不动

| 类别 | 处理 |
|---|---|
| 作者钱包里已提走的余额 | **不动**。这是已属于他的财产;继承人持私钥即可使用 |
| 节点收益账户里已应计、未提取的收益 | 宽限期满后转入新人基金 |
| 此后持续产生的版税和奖励池分成 | 宽限期满后改为流入新人基金 |

知识本身的状态不受影响:作者离世后知识照样被引用、照样计重要性,只是受益人从作者换成了新人。

**已接受的漏洞(D9)**:作者可能把私钥交给子女,由子女继续签名报平安,链上无法分辨。本稿不引入实名,靠 4 年静默期和 105 岁上限把这种情况限制在有限的时间内。

### 6.5 新人基金

- **谁是新人**:首个被接受的贡献发生在最近 **3 年**内,且累计收入低于门槛。
- **怎么分**:每周期释放基金余额的 **20%**(平滑发放),按新人当期贡献的 ΔK 加权分配。
- **防刷**:只有被接受的贡献参与;传承类贡献没有 ΔK,不参与;单账户单周期有领取上限。

这形成代际循环:老一代留下的知识持续被引用,其收益养活下一代探索者,也顺带缓解了冷启动。

## 7. 传承类节点

| 方面 | 规则 |
|---|---|
| 增发 | 不参与 ΔK 增发(D4),`I₀ = 0`,防止编造生平刷币 |
| 准入 | 作者签名 + ≥2 名见证人背书。背书证明的是"谁写的",不是"内容是否属实" |
| 存储 | **捐赠本金**一次性存入节点收益账户,按周期扣租金;本金耗尽前不退场 |
| 隐私 | 正文链下加密存储,链上只存内容哈希、元数据和背书签名。需要销毁时销毁密钥(加密粉碎),内容即不可读 |
| 引用 | 可以引用理论和领域知识。单份家训的引用很少,但大量家训引用同一条文化知识时,那条知识的重要性会涌现出来 |
| 收益 | 不参与奖励池;可被引用,但几乎不产生收益,保存靠本金 |

传承类与认知图谱的连接点在于:**个人的传承贡献"引用",被引用的公共文化知识因此"在世"并获得奖励。**

## 10. 前置条件:嵌入与内容的绑定

当前嵌入向量由提交者自己给出,链上只存向量、看不到内容,也不验证这个向量是否真的从内容计算而来。
攻击者可以在嵌入空间里随手造一个方向,新颖度直接拉满;同一份内容换个方向重报,每次都能领奖。
本仓库的 `./cmd submit` 演示本身就是这样做的(每次按 nonce 旋转单位向量以保持"新颖"),说明这不是
理论风险。目前唯一的防线是评审人,但评审人打的是内容质量分,并不核对向量与内容是否对得上。

| 方案 | 做法 | 代价 |
|---|---|---|
| A. 内容承诺 + 统一模型 | 链上承诺内容哈希;协议规定嵌入模型与版本;评审人取得内容后重算向量,对不上即判拒 | 成本最低,仍依赖评审人诚实 |
| B. 验证人重算 | 内容公开,所有验证人用同一模型重算 | 浮点推理难以跨机器逐位一致,而共识要求完全一致;链要承担存储与计算 |
| C. zkML / opML 证明 | 提交者附"该向量确由该内容经该模型算出"的证明(白皮书 B.5) | 最可靠,技术尚不成熟、成本高 |

**建议:先做 A,长期走 C。** 本稿对此有部分缓解:持续收入从"一次性 ΔK"转向"被他人引用",而他人的
引用比自报的向量更难伪造。但稿费(`I₀`)和初始重要性仍依赖嵌入,所以 A 应排在 §12 所有共识改动之前。

## 11. 博弈与风险

| 攻击 | 缓解 |
|---|---|
| 引用农场:大量小号互相引用 | 引用权重取引用方的重要性,新节点权重很低;同作者引用为 0;单节点引用有上限 |
| 撒网引用:一个节点引用大量热门知识,蹭上溯分成 | 单节点引用上限;上溯分成来自被引方收入,引用方本身不因引用获益 |
| 零余额小号批量刷引用 | 引用余额门槛随条数递增(D11);引用权重取引用方重要性 |
| 新人基金刷取 | 只按被接受贡献的 ΔK 分配;单账户单周期封顶;传承类不参与 |
| 编造生平刷币 | 传承类不参与增发,只能靠自己出的本金保存 |
| 虚报出生年份 | 出生年份需 ≥2 名见证人背书;即使造假,静默推定(4 年)仍然生效 |
| 继承人代签报平安 | 已接受(D9),由 4 年静默与 105 岁上限限时 |
| 恶意证伪竞争对手的知识 | 证伪需评审人声誉加权过半,与知识准入同一门槛;证伪失败可罚没发起方押金 |
| 租金使状态无界增长 | 休眠 2 年后归档,移出活跃状态集 |

## 12. 实施拆分(建议)

**先仿真,后编码。** 这套机制的参数(半衰期、门槛、租金、释放比例)互相牵制,应先扩展 `sim/` 的智能体仿真,验证奖励池不枯竭、新人基金不被刷穿、租金不把正常知识挤出,再定默认值。

| 阶段 | 内容 | 共识影响 |
|---|---|---|
| L0 | `sim/` 扩展:分层、引用、重要性衰减、租金、存活与新人基金 | 无 |
| L1 | 数据模型:层级字段、引用边、节点状态、节点收益账户 | wire + `state_root` + 快照 |
| L2 | 重要性记账(惰性衰减)+ 周期结算 + 在世知识奖励池 | `state_root` |
| L3 | 存储租金、自然期限、休眠与归档 | `state_root` |
| L4 | 账户存活:心跳、推定离世、宽限托管、新人基金 | 新操作 + `state_root` |
| L5 | 传承类节点:捐赠本金、见证人背书、加密正文哈希 | 新交易类型 |
| L6 | 证伪与取代的评审操作 | 新操作 |
| L7 | 浏览器:重要性排行、生命周期状态、新人基金看板 | 无 |

L1 到 L6 都是共识变更,建议在 L1 之前先完成嵌入与内容的绑定(§10),否则新的经济机制会建立在一把可以被随意摆弄的尺子上。

## 13. 开放问题

1. 结算周期的长度:越短越精确,越长越便宜。
2. 已取代节点的转记比例应否随时间递减。
3. 跨层引用是否需要约束,例如应用层能否直接引用理论层(本稿允许)。
4. 嵌入模型的选择与升级:模型升级后旧节点的嵌入如何迁移,是否需要按模型版本分区比较新颖度。
