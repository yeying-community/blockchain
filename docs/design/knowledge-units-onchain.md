## 1. 目标与范围

把 VISION 中已确定的知识单元模型搬上链,使社区驱动的测试网能在链上**创建知识、发布版本、建立引用、记录核验、
计算可信度、邀请新成员**。测试网积累的知识与核验记录,将作为主网的创世数据。

| 阶段 1 包含 | 阶段 1 不包含(留给阶段 2) |
|---|---|
| 知识单元、版本、层级、领域 | 押金、挑战、裁决 |
| 两类引用(依据 / 参见),版本锁定 | 担保人连带责任(只做邀请,不做连带处罚) |
| 核验记录 | 奖励池、存储租金、生命周期状态转换 |
| 可信度计算(与 `tools/kgraph.py` 同一规则) | 存活判断与新人基金 |
| 邀请新成员(含见习期) | 证伪、取代的评审操作 |
| 内容许可 CC BY 4.0(协议强制) | 链上存储正文 |

阶段 1 **不涉及任何代币发放**:知识操作不增发,也不收费(只需账户序号防重放)。这让测试网天然不存在"刷分换收益"的动机。

## 2. 数据模型

```
Member(账户扩展)
  id, pubkey, joined_height, inviter            // inviter = 0 表示创世成员

KnowledgeUnit
  id                     u64,单调分配
  author                 u64,创建者
  layer                  Foundation | Explanation | Scenario | Application
  domain                 u32,领域命名空间(1 = 大模型应用开发,2 = 运动健身;由创世登记)
  created_height
  versions               Vec<UnitVersion>,v1 起连续编号

UnitVersion
  n                      u32
  publisher              u64,发布该版本的成员(作者或修订者)
  bodies                 Vec<(lang, sha256)>,每种语言正文的哈希(U2:多语言算同一条)
  source                 Human | Model(model_id) | ModelVerified(model_id)
  cites                  Vec<Cite>
  published_height

Cite
  unit, version          被引用的单元与其版本(版本锁定,U1)
  kind                   Basis(依据)| SeeAlso(参见)

Verification
  unit, version, verifier, verdict: Pass | NeedsRevision, note_hash, height
```

**内容许可**:协议常量 `CONTENT_LICENSE = "CC-BY-4.0"`。所有版本默认以该许可发布,提交即视为同意;
许可标识折入 `state_root`,主网迁移时随数据一起验证。

**正文不上链**:链上只存每种语言正文的 SHA-256。测试网阶段,正文存放在内容寻址的 Git 仓库中(以哈希为文件名),
任何人可按哈希取回并核对。正文由谁长期存储归入 VISION Q5。

## 3. 操作

全部为账户签名操作,使用账户序号防重放,沿用治理操作的成熟模式(gossip、待处理池、容量与按账户配额、
出块前过滤、RPC 提交、离线授权 CLI)。

| 操作 | 字段 | 规则 |
|---|---|---|
| `CreateUnit` | layer, domain, 首个版本(bodies, source, cites) | 作者须为成员;domain 须已登记 |
| `PublishVersion` | unit, bodies, source, cites | **任何成员都可发布新版本**(Q2 决定:原作者不独占修改权);新版本可信度从零开始,须重新核验 |
| `Verify` | unit, version, verdict, note_hash | 核验人 ≠ 该版本发布者;核验人须已过见习期;同一人对同一版本重复核验,以最新结论为准 |
| `Invite` | new_pubkey | 邀请人须已过见习期;每人每周期邀请数有上限;新成员 id 单调分配,记录邀请人 |

**引用校验**:被引用的单元与版本必须已存在;不能引用自身;单个版本最多 32 条引用。
因为新版本只能引用**已经存在**的版本,版本级的引用图**天然无环**,"依据不能成环"由构造保证,无需额外检测。

**见习期**(M7):新成员在 `PROBATION_BLOCKS` 内可以创建单元、发布版本,但其核验不计入可信度、不能邀请他人。
这是仿真第三轮的结论在阶段 1 的最小落地:**新人的分量从零起步,否则换号即洗白**。

## 4. 可信度

与 `tools/kgraph.py` 试运行规则 v0 **完全一致**,用定点整数(万分比)计算,保证跨平台确定:

```
自身可信度(单元 u 的版本 v)
  = 1000  若来源为模型生成且无人核验通过
  = 2000  否则
  + 2000 × (对 v 核验通过、且已过见习期、且 ≠ 发布者 的不同成员数)
  上限 9000

有效可信度 eff(u, v) = min( 自身可信度(u, v), min over 依据引用 (d, w) of eff(d, w) )
```

依据引用锁定被引用的版本,所以 `eff(d, w)` 用的是**被引用时那个版本**的可信度。被引用单元发布了新版本,
旧引用仍指向旧版本;RPC 会提示"引用基于 v1,当前已是 v2"。

**可信度是派生量,不折入 `state_root`**:它完全由已入链的单元、版本、核验记录决定,在查询时计算。
阶段 2 若需要用它分配奖励,再考虑缓存与折入。

## 6. 读取与工具

- **RPC**:`POST /knowledge`(提交编码后的操作);`GET /units`、`/unit/{id}`、`/unit/{id}/versions`、
  `/unit/{id}/credibility`(含"被谁卡住")、`/members`。沿用现有 JSON / 文本内容协商与分页约定。
- **CLI**:`node encode-knowledge-op`(create / publish / verify / invite),`node hash-content --file`。
- **导入工具**:`tools/kimport.py` 读取 `docs/pilot/<领域>/` 下的单元文件,计算正文哈希,生成并提交操作。
- **一致性测试**:同一份试运行数据,链上计算的可信度必须与 `tools/kgraph.py` 逐条一致。
- **浏览器**:新增"知识"页:单元列表、版本历史、引用关系图、可信度与瓶颈。

## 7. 主网迁移(VISION §4d)

主网创世写入测试网最终知识快照的哈希与测试网最后区块的哈希,任何人可从测试网历史重新计算并核对。

| 迁移 | 不迁移 |
|---|---|
| 知识单元、全部版本、引用、来源标注、许可 | 代币余额 |
| 核验记录 | 信誉(主网按主网规则,从迁移的记录重新计算) |
| 贡献记录(谁写了什么、谁核验了什么) | |
| 成员与邀请关系 | |

对早期贡献者的回报,**不提前承诺任何兑换关系**,主网上线后由治理决定。
