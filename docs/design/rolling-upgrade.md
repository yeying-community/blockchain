# 设计:滚动升级 / Rolling upgrade (multi-wire) — production-readiness §10 #7

> 状态:**设计稿**,供评审后分片实现。对应 [`docs/SECURITY.md` §10 第 7 项](../SECURITY.md)
> 与 DEPLOYMENT §9「不支持多版本并存滚动升级」。
>
> **实现进度**:**S1 已落地(M221)**——传输层版本**区间协商**(`[MIN_WIRE_VERSION,
> PROTOCOL_VERSION]`,取最高公共版本,无交集拒连),替代 M192 的单值严格相等。当前区间 `[3,3]`
> ⇒ 功能等价,但握手由 4 字节改 8 字节(一次性引导破坏)。剩余 S2–S4(按高度解码分派、激活机制、
> 首次 B8 滚动升级演练)待 real wire 升级需求时推进。

## 1. 动机

今天升级一次破坏 wire 的版本需要**协调全网停机**(DEPLOYMENT §9:公告窗口 → `SIGTERM` 全停 →
换二进制 → 必要时重 snap → 同步重启)。对生产主网这意味着每次协议升级都有一段**全网不可用**,
且要求所有运营方精确同步操作——易错、难协调、与「高可用」相悖。

滚动升级让运营方**逐个**替换验证人二进制、网络全程保持 >2/3 在线出块,新协议在一个**协调激活
高度**原子切换。这是 Tendermint / 以太坊「按高度硬分叉」的标准模型。

## 2. 当前状态(单版本,严格拒绝)

- **传输协商**(M192):连接最前 4 字节交换 `PROTOCOL_VERSION`(当前 **3**),**严格相等**否则
  `InvalidData` 拒连(`daemon.rs::negotiate_version`)。无版本区间。
- **wire 代际**:`codec` 同一时刻只讲**一个**代际(B2→B7);`decode_block`/`decode_certified_header`
  按固定偏移(B7 前缀 284B)解码,**只认当前代际**。旧代际帧 → 解码垃圾 / 错误。
- **快照**:`SNAPSHOT_VERSION`(当前 **5**)严格相等,旧版拒绝。
- **升级**:协调停机 + 换二进制(+ 必要时重 snap),无并存。

**根因**:节点既不能**解码**异代际帧,也没有「何时切换**生产**代际」的协调机制。

## 3. 关键不变量(为何不能简单地「各自升级」)

被哈希的编码(`Block`/`BlockHeader` → `block.hash()` → `prev_hash` 链 + cert 签名)**必须在同一
高度跨所有节点逐字节一致**。否则两个诚实节点对同一高度算出不同 block hash → **分叉**。

因此 wire 代际切换**不能**按节点各自升级时间发生,必须按**协调高度 H\*** 原子发生:H\* 之前所有
(已升级的)节点仍**生产旧代际**,H\* 起全部**生产新代际**。已升级节点在 H\* 前必须能**生产旧**、
**解码新旧两者**。

## 4. 两层模型

滚动升级是**两个独立层**,勿混:

| 层 | 对象 | 切换粒度 | 机制 |
|---|---|---|---|
| **A. 传输/gossip** | 连接上的帧分发(`GossipMsg` 分帧) | **逐连接** | 版本**区间**协商,取双方最高公共版本 |
| **B. 共识 wire** | 被哈希的 `Block`/`Header`/`Cert` 编码 | **逐高度(H\* 原子)** | 按激活高度选择编码代际 |

- A 让**已升级与未升级节点仍能互相解码 gossip**,从而可逐个换二进制(升级期网络不分区)。
- B 保证**被哈希的区块编码在每个高度全网一致**(H\* 前旧、H\* 起新),避免分叉。

## 5. A 层:传输区间协商

`negotiate_version` 由「交换单值 + 严格相等」改为「交换 `[min, max]` 支持区间 + 取公共最高」:

```
握手:各方写 (min_u32, max_u32);读对端区间。
公共 = min(my_max, peer_max);若 公共 < max(my_min, peer_min) ⇒ 无交集 ⇒ 拒连。
否则该连接的帧用「公共」版本编解码。
```

- 二进制维护 `[MIN_WIRE, MAX_WIRE]`(如升级版支持 `[3,4]`,旧版 `[3,3]` → 公共 3,仍能通信)。
- `GossipMsg` 分帧/编码按连接的协商版本走(多 `encode_gossip_vN`/`decode_gossip_vN` 或版本化字段)。
- 安全注记同 M192:区间协商在 `require_peer_auth` 认证**之前**,MITM 篡改区间只致**拒连**(非降级)。

## 6. B 层:按高度激活共识 wire

- **激活高度 H\***:新代际从 H\* 起成为 canonical。来源二选一(建议都支持):
  1. **genesis/config 升级时刻表**:`[[upgrades]] name="B8" height=H*`(运营方带外约定 H\*)。
  2. **链上治理**:一个 `GovParam::WireActivation{gen, height}` 提案过双门槛后把 H\* 写入状态
     (复用 M193–198 治理路径)。治理式更去中心、可审计,但需 H\* 足够远以留升级窗口。
- **编码分派**:`encode_block`/`decode_block` 等按「该高度生效的代际」选择布局:
  - 生产:`seal` 时按 `height >= H*` 选新/旧编码。
  - 解码:`decode_block(height, buf)` 按高度选解码器(或帧自带代际标签,见 §7 取舍)。
- **cert / header**:`decode_certified_header` 的固定前缀随代际不同 → 需按代际解码(前缀长度分派)。
- **快照**:`SNAPSHOT_VERSION` 继续严格;跨激活的快照用新版导出。

## 7. 解码器策略与取舍

**保留旧解码器**:wire 破坏时**不删**旧代际 `decode_*`,新增 `decode_*_vN`,`decode_block` 变为
按代际分派。代价:codec 体积随支持代际数增长 → 维护一个**滑动支持窗口**(只保留最近 K 代,更老的
经「重 snap + 干净拒连」淘汰,回到今天的模型)。

**代际来源**:解码时如何知道该用哪代?两种:
- **按高度**(推荐,用于区块/cert/header):调用方已知高度(同步、apply),传入 `decode_*(height, buf)`,
  按 H\* 表选代际。无需改 wire(不加标签)。
- **按帧标签**(用于传输层 gossip,无「高度」上下文):A 层协商版本决定 `decode_gossip_vN`。

## 8. 升级流程(运营方视角,目标形态)

1. 公告:新二进制 + 激活高度 H\*(或提交治理提案),H\* 留足窗口(如 +N 万高度)。
2. **逐个**替换验证人二进制为支持 `[old, new]` 的版本;每个升级后经 A 层仍与未升级节点通信,
   网络全程 >2/3 在线出块,**无停机**。
3. 到 H\*,所有(已升级)节点自动切换生产新代际;未在 H\* 前升级的节点此后**无法跟随**(其编码
   在 H\* 后与网络不一致)→ 掉队,需升级后重同步。
4. 窗口过后可在更晚版本移除对最老代际的支持(滑动窗口)。

## 9. 分片实现计划

- **S1(版本区间,零 wire 破坏)✅ M221**:`MIN_WIRE_VERSION` + `negotiate_version` 改区间协商
  (写 `[MIN_WIRE_VERSION, PROTOCOL_VERSION]`、读对端、取最高公共版本、无交集 `InvalidData` 拒连、
  返回协商版本供 S2 选 gossip 编解码)。当前区间 `[3,3]` ⇒ 功能等价。一次性握手破坏(4→8 字节)
  同 M192 性质。回归:`version_negotiation_{accepts_matching_peers,agrees_on_highest_common,
  rejects_disjoint_ranges,rejects_older_wire_gen}`;localnet/daemon 集成测试经真实 `handle_conn`
  仍收敛。
- **S2(按高度解码分派)**:`decode_block`/`decode_certified_header` 接 `height`(或代际),引入
  代际表;当前仅 B7,分派表单条目,行为不变;为将来新增代际留位。
- **S3(激活机制)**:genesis `[[upgrades]]` 时刻表解析 + `seal`/apply 按 H\* 选编码;(可选)治理
  `WireActivation` 提案。
- **S4(首次真·滚动升级演练)**:造一个 B8(加字段)走全流程:逐个升级 + H\* 激活 +
  `testnet/` 演练脚本证明升级期不停机、H\* 后收敛。

## 10. 风险 / 非目标

- **风险**:节点未在 H\* 前升级 → 掉队(活性,非安全——它不会造成全网分叉,只是自己跟不上)。
  运营需监控版本就绪度(可加 `zhixing_wire_version` 指标 + 告警)。
- **风险**:治理式激活若 H\* 定太近,慢运营方来不及升级 → 掉队面扩大。建议最小提前量硬下限。
- **非目标**:**降级**(新→旧不支持)、任意版本全连通(只支持滑动窗口内相邻几代)、跨实现互操作。
- **与其它 wire 破坏项的耦合**:liveness auto-jailing(需内嵌 canonical `last_commit`,见
  [`liveness-participation-constraint`] 记忆)与任何未来 wire 破坏都应**走本框架的 H\* 激活**,
  而非再来一次协调停机。这正是先建滚动升级框架的价值。
