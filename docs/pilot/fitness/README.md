## 写应用知识,会暴露缺失的基础知识

最初只起草了"渐进超负荷"和"深蹲"。深蹲引用的超量恢复、核心稳定、关节的稳定与灵活、运动前自我评估
四条原理当时都不存在,随后补齐,形成一张连通的小图。**上层知识会把下层的空缺拉出来。**

## 怎么核验

1. 打开单元末尾的"核验要点",逐条确认;
2. 在"核验记录"表里填一行:核验人、核验的版本、结论(通过 / 需修改)、日期、说明;
3. 运行 `python3 tools/kgraph.py docs/pilot/fitness`,查看可信度变化与下一个优先核验的单元。

**建议从基础单元开始核验**:应用单元的有效可信度不会超过它所依据的基础单元。

## 导入链上(K6)

```sh
./cmd up            # 本地单节点链(创世已登记领域 1 大模型应用开发、2 运动健身)
./cmd knowledge     # 导入本目录 6 个单元(作者为账户 1),正文按哈希存入 .localnet/bodies
./cmd kverify 2 5 1 # 账户 2 核验单元 5 的 v1
./cmd units         # 查看各单元的链上可信度与瓶颈
```

导入工具 [`tools/kimport.py`](../../../tools/kimport.py) 与 `kgraph.py` 共用解析器。"渐进超负荷"与"超量恢复"
互为"参见",而链上一个版本只能引用已存在的版本,所以导入时先创建、再为"渐进超负荷"发布 **v2** 补上参见。
因此它的 v1 核验不会带到 v2(核验只对当时的版本有效),而"深蹲"锁定引用的是 v1,不受影响,并提示"引用已过时"。
