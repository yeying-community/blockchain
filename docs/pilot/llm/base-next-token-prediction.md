## 核心陈述

生成式语言模型每一步只做一件事:**根据前面所有的词元,给出下一个词元的概率分布**,从中选出一个,接到末尾,
再重复。一篇回答就是这样一个词元一个词元"接"出来的。

## 正文

### 一步在做什么

输入是一串词元。模型计算词表里**每一个**词元作为下一个出现的可能性,得到一个概率分布。例如前文是
"今天天气很",下一个是"好"的概率可能很高,"冷""热"其次,"桌子"几乎为零。
选出一个词元(怎么选见"采样与温度"),拼到输入末尾,再算下一步。遇到表示结束的特殊词元,或达到长度上限,就停下。

### 它是怎么学会的

**预训练**:在海量文本上,遮住每个位置的下一个词元,让模型去猜,猜错就调整参数。为了猜得准,
模型不得不学到语法、事实、常见的推理模式。之后通常还要经过**指令微调**和**基于人类反馈的训练**,
让它学会按用户的要求回答,而不只是续写文本。

### 对开发者意味着什么

1. **模型给出的是"可能的下一个词元",不是"查到的事实"。** 流畅不等于正确,这是幻觉的根源之一。
2. **生成是逐个进行的,输出越长越慢、越贵。** 输出词元通常比输入词元计费更高,也是延迟的主要来源。
3. **前面写出的内容会影响后面。** 已经生成的词元成为下一步的输入,所以先让模型写出推理步骤,常能改善多步问题的答案。

## 自己验证

许多模型接口能返回每个输出词元的对数概率(常见参数名如 `logprobs`,以你所用接口的文档为准)。
请求一个很短的续写并打开该选项,观察:每个位置都有若干候选词元及其概率,被选中的不一定是概率最高的那个
(取决于采样设置)。

也可以用本地的小模型做同样的观察(依赖 `pip install transformers torch`,首次运行会下载约 500 MB 的 GPT-2 模型):

```python
from transformers import AutoTokenizer, AutoModelForCausalLM
import torch
tok = AutoTokenizer.from_pretrained("gpt2"); model = AutoModelForCausalLM.from_pretrained("gpt2")
ids = tok("The capital of France is", return_tensors="pt").input_ids
probs = torch.softmax(model(ids).logits[0, -1], dim=-1)
top = torch.topk(probs, 5)
for p, i in zip(top.values, top.indices):
    print(f"{tok.decode(i)!r:>12}  {p:.3f}")
```

预期:输出前 5 个候选词元及其概率,概率之和小于 1(其余概率分散在词表的其他词元上)。

## 适用范围与局限

- 适用:GPT 类的自回归语言模型,即当今主流的对话与生成模型。
- 不适用:扩散式文本生成等其他生成方式(目前不是主流)。
- 容易过时的部分:"输出比输入贵"之类的计费关系因厂商而异。

## 核验要点(给人类审查者)

1. "为了猜得准,模型不得不学到……"是常见的直观解释,是否需要标注为解释性说法而非已证明的结论?
2. "流畅不等于正确,这是幻觉的根源之一"——幻觉的成因有多种解释,这句话是否写得恰当?
3. GPT-2 示例代码**起草时没有运行**(需下载约 500 MB 模型),请实际运行一遍,确认库接口没有变化、输出与描述一致。
