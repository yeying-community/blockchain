## 核心陈述

模型每一步给出的是下一个词元的概率分布,**采样**决定从中选哪一个。**温度**(temperature)调整分布的尖锐程度:
温度低,高概率的词元更占优,输出更稳定;温度高,分布更平,输出更多样,也更容易跑偏。

## 正文

### 温度怎么起作用

模型先为每个词元算出一个分数(logit),再用 softmax 转成概率。温度 T 的做法是**先把分数除以 T 再做 softmax**:

- T < 1:分数差距被放大,概率集中到少数词元上;
- T = 1:保持模型原本的分布;
- T > 1:分数差距被缩小,低概率的词元也有机会被选中;
- T 趋近 0:几乎总是选概率最高的那个,接近**贪心解码**(greedy decoding)。

### 另外两个常见参数

- **top-k**:只在概率最高的 k 个词元里选;
- **top-p**(核采样,nucleus sampling):按概率从高到低累加,只在累计概率达到 p 的那一小批词元里选。

它们都是在"选哪个"之前先砍掉长尾的低概率词元,避免偶尔选出离谱的词。

### 对开发者意味着什么

1. **要稳定、可复现的输出(抽取、分类、生成 JSON),用低温度;要多样的输出(头脑风暴、改写),用较高温度。**
2. **温度为 0 也不保证每次输出完全相同。** 实际服务中,并行计算的浮点误差等因素可能让结果有细微差别。
   需要严格可复现时,要把输出存下来,而不是指望重新生成。
3. 不同接口的温度取值范围和默认值不同,同一个数值在不同模型上的效果也不同,要以所用接口的文档为准。

## 自己验证

不需要调用任何模型,用标准库就能看到温度对分布的影响:

```python
import math

def softmax_t(logits, t):
    m = max(x / t for x in logits)
    e = [math.exp(x / t - m) for x in logits]
    s = sum(e)
    return [x / s for x in e]

logits = {"好": 4.0, "冷": 3.0, "热": 2.5, "桌子": -1.0}
for t in (0.2, 1.0, 2.0):
    p = softmax_t(list(logits.values()), t)
    print(f"T={t}: " + "  ".join(f"{k}={v:.3f}" for k, v in zip(logits, p)))
```

预期:T=0.2 时"好"的概率接近 1;T=1.0 时"好"约 0.6,"冷""热"也有一定概率;T=2.0 时分布明显变平,
"桌子"的概率也不再是零。

再用真实模型对比:同一个提示在低温度和高温度下各请求 5 次,比较输出的差异。

## 适用范围与局限

- 适用:逐个词元采样生成的语言模型。
- 不适用:部分接口在某些模式下(例如一些推理型模型)固定或忽略温度参数,以文档为准。
- 容易过时的部分:各接口的参数名、取值范围、默认值。
