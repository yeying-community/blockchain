## 核心陈述

大模型读进来、写出去的单位不是"字"也不是"词",而是**词元**(token):由分词器(tokenizer)把文字切成的片段,
每个片段对应词表里的一个编号。同一段文字在不同模型上切出的词元数可能不同,而上下文长度、速度和计费都按词元算。

## 正文

### 为什么不直接用字或词

- **用整词**:词表要大得惊人,而且遇到新词、错别字、专有名词就无从表示;
- **用单个字符(或字节)**:什么都能表示,但序列太长,模型要处理的步数成倍增加。

**子词分词**(subword tokenization)取两者之间:常见的词或片段整体成为一个词元,罕见的词拆成几个更小的片段,
最坏情况下退到单个字节,所以任何文字都能表示。字节对编码(Byte Pair Encoding,BPE)是常见做法之一:
从单个字符开始,反复把语料里最常一起出现的相邻片段合并成新的词元,直到词表达到预定大小。

### 对开发者意味着什么

1. **词元数 ≠ 字数 ≠ 单词数。** 常见英文单词往往是一个词元;中文、代码、数字、生僻词切法差别很大。
   网上流传的换算比例只是某些分词器在某类文本上的粗略经验,**要以实际测量为准**。
2. **不同模型的分词器不同。** 同一段提示,换一个模型,词元数可能明显变化,计费和是否超出上下文窗口也随之变化。
3. **模型"看到"的是词元,不是字母。** 这是模型有时数不清一个单词里有几个某字母、处理逐字符任务不稳定的原因之一:
   它看到的是几个片段的编号,而不是一个个字母。

## 自己验证

用开源的分词器看同一段文字被切成什么样(依赖 `pip install tiktoken`,这是某一家模型的分词器,仅作演示;
你用的模型请查它自己的分词工具或接口返回的用量字段):

```python
import tiktoken
enc = tiktoken.get_encoding("cl100k_base")
for text in ["hello world", "unbelievably", "知行图是一张知识图谱", "x = foo(42)"]:
    ids = enc.encode(text)
    print(f"{len(text):>3} 字符 → {len(ids):>2} 词元  {[enc.decode([i]) for i in ids]}")
```

预期:常见英文单词多为一个词元;长词被拆成几段;中文的切法与英文不同;部分片段单独解码时可能不是完整的字
(一个汉字的字节被拆在两个词元里)。换另一个编码(如 `o200k_base`)再跑一次,词元数会不同。

起草时的实际运行结果(tiktoken 0.14.0,2026-11):

```
 11 字符 →  2 词元  ['hello', ' world']
 12 字符 →  3 词元  ['un', 'belie', 'vably']
 10 字符 → 12 词元  ['知', '行', '图', '是', '一', '张', '知', '�', '�', '图', '�', '�']
 11 字符 →  6 词元  ['x', ' =', ' foo', '(', '42', ')']
```

同一句中文换成 `o200k_base` 是 8 个词元。注意"识"和"谱"各被拆成两个词元,单独解码时显示为 `�`。

## 适用范围与局限

- 适用:几乎所有当今主流的大语言模型。
- 不适用:也有直接在字节或字符上建模的模型,但不是当前主流。
- 容易过时的部分:具体某个模型用哪种分词器、词表多大。
